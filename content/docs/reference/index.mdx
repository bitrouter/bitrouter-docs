<Callout type="warn">
The BitRouter API is in early beta. Pin your integration to the behavior you test and review release notes before upgrading.
</Callout>

Base URL: `https://api.bitrouter.ai`

Choose the API family that matches your task:

| Need | Start with |
| --- | --- |
| Send a model request in an existing SDK format | One of the four inference APIs |
| Discover available models | Models |
| Manage Cloud accounts, keys, usage, billing, or policy | Cloud management |
| Check node health or scrape metrics | Health or Metrics |

## Route a request

Choose the protocol your client already speaks. BitRouter keeps the request and response shape for that protocol while routing the requested model to an eligible upstream.

<Cards>
  <Card title="OpenAI Chat Completions" href="/docs/reference/openai-compatible/createChatCompletion" description="POST /v1/chat/completions" />
  <Card title="OpenAI Responses" href="/docs/reference/openai-responses/createResponse" description="POST /v1/responses" />
  <Card title="Anthropic Messages" href="/docs/reference/anthropic-compatible/createMessage" description="POST /v1/messages" />
  <Card title="Google GenerateContent" href="/docs/reference/google-compatible/googleGenerateContent" description="POST /v1beta/models/{model}:generateContent" />
</Cards>

Routing endpoints accept either:

- `Authorization: Bearer <api-key-or-JWT>`
- `x-api-key: <api-key>` for Anthropic-compatible clients

```bash
curl https://api.bitrouter.ai/v1/chat/completions \
  -H "Authorization: Bearer $BITROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-haiku-4.5",
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

## Manage and inspect BitRouter

Model discovery, BYOK encryption bootstrap, health, and metrics are public. BYOK provider eligibility requires `byok:read`; account-bound management endpoints require a credential with the scope named by that endpoint.

## Provider discovery migration

The public `GET /v1/providers` directory is removed from the API described here. After the corresponding Cloud release, that path returns `404`, and the former `?provider=` filter on `GET /v1/models` returns `400`. Use [Models](/docs/reference/discovery/listModels) to discover canonical model IDs and their BitRouter prices.

For BYOK setup, call [List BYOK-eligible providers](/docs/reference/byok/listByokProviders) with a credential that has `byok:read`. Its authenticated response lists provider IDs and display labels that accept portable API keys. Existing account policy and preset provider controls remain available separately from public model discovery.

This reference describes the hosted Cloud API. For the local daemon lifecycle, configuration, and virtual keys, use [Self-hosting](/docs/self-hosting); for the generated CLI surface, use [CLI](/docs/usage/cli).
