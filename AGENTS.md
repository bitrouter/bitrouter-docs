# bitrouter-docs

Next.js 16 (App Router) + fumadocs site for [bitrouter.ai](https://bitrouter.ai) — landing, models catalog, recipes, blog, changelog, and the documentation under `content/docs/`.

## Documentation rules

- **English only.** The site no longer ships localized docs — do not create `<name>.zh.md` translation files or reintroduce i18n plumbing. Old `/zh/*` URLs 301 to the English pages via `next.config.ts` redirects.
- Docs are **`.mdx`**, import-free, using only the whitelisted global components — see `docs/CONTRIBUTING.md` for the full authoring contract. Write Markdown; the extension is what makes `<Callout>` / `<Cards>` / `<Tabs>` actually render (fumadocs-mdx picks its processor by extension, and `.md` silently drops those blocks).
- Lint with `pnpm lint:docs` (`scripts/check-docs.mjs`) after editing docs.
- Documentation is one unified Fumadocs page tree with no layout tabs. Its eight user-facing groups are **Overview, Usage, Coding Agents, Market, Router, Model, Context, Reference**. In `content/docs/meta.json`, each group name is a native Fumadocs separator and each meta-only `*-nav` folder is extracted into the root, so group labels are not clickable or collapsible. Changelog is one page at `/docs/changelog` under Reference, generated from `content/changelog/`; old release URLs redirect to version anchors. RSS/Atom stay at `/changelog/rss.xml` and `/changelog/atom.xml`.
- **Show every non-Reference page in the sidebar exactly once unless it is an explicit product-navigation exception.** Overview, Usage, Coding Agents, Market, Router, Model, Context, and Reference use flat link lists beneath their separators, with Comparison under Overview and API reference under Reference as explicit collapsed-folder exceptions; do not hide detailed pages or introduce other nested guide folders by default. Intentional hidden pages must remain rare and be listed in `HIDDEN_SIDEBAR_ROUTES` in `scripts/check-docs.mjs`; currently Cloud, Supported Models, Self-hosting, BitRouter Agent, the supporting Request receipts guide, the shared `bro [harness]` guide, and the retained Coding agents guide are hidden. Local Models is visible. `pnpm lint:docs` enforces this coverage.
- **Overview order is Quickstart, How BitRouter Works, Inference Spot, Inference Forwards, then Comparison.** Inference Spot and Inference Forwards are Coming soon placeholders. Supported Models remains accessible at `/docs/overview/supported-models` without a sidebar entry. How BitRouter Works retains `/docs/overview/what-is-bitrouter`.
- **Overview contains a collapsed Comparison folder.** Its header only expands/collapses the folder, with no index page; its four children are OpenRouter, Router (Ramp), vLLM Semantic Router, and LiteLLM. `(comparison-nav)/meta.json` projects those canonical pages into Overview. Keep competitor claims sourced to current official documentation and qualify deployment/build availability. The retired `/docs/overview/comparison` URL redirects to the first child. Point content links and legacy migration redirects directly at the corresponding child.
- **Usage** contains exactly Desktop, CLI, Responses API, MCP, and Web, in that order. MCP and Web are Coming soon placeholders. The Cloud placeholder remains accessible at `/docs/usage/cloud` without a sidebar entry. Usage MCP is separate from the Context MCP servers configuration/use guide. Desktop is Coming soon until its implementation is verified. CLI combines Self-driving, Interactive TUI, and Headless & Scripting at `/docs/usage/cli`, retaining all preview qualifications. **Reference** contains Changelog, Privacy Policy, Terms of Service, Troubleshooting, and API reference, in that order. Privacy Policy and Terms of Service are authored docs pages at `/docs/privacy-policy` and `/docs/terms-of-service`; migrate their existing prose without changing policy commitments. Troubleshooting is a Coming soon placeholder. API reference remains the collapsed `content/docs/reference/` folder, with static family separators and directly visible endpoints plus the Decisions and compatibility guides. CLI command reference is embedded in `/docs/usage/cli#command-reference`; schema-generated configuration reference is embedded in `/docs/routing/configuration#configuration-reference`. Data handling is retired and redirects to Privacy Policy. Make generated hierarchy changes in scripts, never generated metadata.
- **Market** follows Coding Agents and precedes Router. It contains Buy Inference and Sell Inference at `/docs/market/`. Both currently have titles and descriptions only; detailed marketplace behavior remains unverified. Market owns buying and selling workflows and future trading, delivery, and settlement guides. Connecting an endpoint belongs to Model; offering its inference for sale belongs to Market.
- **Router** replaces the Routing section label and contains exactly Auto Router, Routing Rules, Context Routing, and Configuration (YAML), in that order. Canonical guides remain under `/docs/routing/`: `auto-router`, `routing-rules`, `context-routing`, and `configuration`. Auto Router owns `bitrouter/auto` setup, policy bindings, adequacy, objective evaluation evidence, and reviewed publication. Routing Rules owns selector resolution, candidate eligibility, preset routing filters, named `variants:`, and ordering limits; the former Model Variants page redirects to its Variants section. Context Routing owns native evidence views. Configuration (YAML) owns common file mechanics and policy artifact boundaries. The retired Strategies page is split between Auto Router and Routing Rules, with legacy anchors retained on Auto Router for moved rule sections. Routing selects among sources the caller can already access, including BYOK, local, private, and purchased sources; buying and selling are optional and routing does not grant access or purchase supply. Keep rule-authoring examples in Routing Rules and policy lifecycle examples in Auto Router.
- **Model** owns source connections and callable interfaces, with exactly five visible guides in this order: Model Fallbacks, Virtual Models, Structured Output, BYOK & Subscriptions, and Local Models. These guides live under `/docs/models-routing/`. Structured Output is a Coming soon placeholder; existing API response-format documentation remains in Responses API. Model owns credentials, subscription accounts, custom endpoints, self-run inference, named endpoints, request defaults, protocol compatibility, and fallback configuration. Named routing variants belong to Router rather than Model. Custom Provider is retired; its URL redirects to the custom endpoints section of BYOK & Subscriptions. Keep feature configuration examples in their owning guides and link to them from Router.
- **Context** shows ACP servers, MCP servers, Agent Skills, and Server tools. Server tools currently has a title and description only while its implementation is being refactored. Native context selection belongs to Router, separately from Context's tool, agent, and instruction connections. The former Config Server tools guide is retired; its URL redirects to the Context placeholder. **Usage > CLI** combines Self-driving workflows, Interactive TUI, and Headless & Scripting. Self-driving (retaining the product name BitRouter Orchestrator/BRO in its body) and Interactive TUI are goal-oriented design previews based on 006 PRD v0.8, pending implementation validation; Headless & Scripting covers development-native `bro task run` / `bro task managed`, structured output, verification, and Goal automation boundaries; full Goal scripting remains unverified. External one-prompt ACP invocation and approval policies live in ACP servers, linked from the generated command reference. Native launch belongs to Coding Agents and does not create a Goal. Keep captured CLI reference output source-faithful until a verified binary snapshot supports the new contract. Configuration is canonical at `/docs/routing/configuration`; the former CLI configuration URL redirects there. Request receipts remains directly accessible and linked from feature guides, without a sidebar entry. **Coding Agents** shows Claude Code, Codex, DeepSeek Harness, OpenCode, and Pi, in that order. These product-specific pages are Coming soon placeholders. The shared `bro [harness]` launch guide remains accessible at `/docs/integration/bro-harness` without a sidebar entry. **Usage > Responses API** owns the default generation guide; **API reference** owns Decisions / System One, Chat Completions / Messages, and generated endpoints. Keep each configuration example with the feature it configures; share it through links. Self-hosting owns deployment operations and OTLP exporter setup, content capture, and sampling. Enterprise is the Overview decision entry.
- Retiring or moving a page means adding a 301 to the `pairs` list in `next.config.ts` — that file is the URL history of the docs.
- **Always use the scripts — never hand-edit generated output.** Anything produced by a generator is regenerated at `prebuild`, so manual edits are silently lost:
  - API reference (`content/docs/reference/<tag>/`) — edit `openapi.yaml`, then `pnpm generate:openapi`.
  - CLI guide and inline command reference (`content/docs/(guide)/usage/cli.mdx`) — edit `cli-overlays/guide.md` for the workflow guide, `cli-overlays/index.md` for the reference intro, or `cli-overlays/<group>.md` for command sections, then `pnpm generate:cli`. The full published CLI page is generated; never edit it directly.
  - Configuration guide with inline schema reference (`content/docs/(guide)/routing/configuration.mdx`) and downloadable schema — edit `config-reference/guide.md` for the configuration workflow or `config-reference/index.md` for reference prose; refresh the pinned upstream schema with `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>`, then `pnpm generate:config`. Never hand-edit `config-reference/schema.json`, `config-reference/source.json`, or `public/schemas/bitrouter.config.schema.json`.
  - `.cli-snapshot.json` — re-capture from the binary with `pnpm snapshot:cli`; never edit by hand.
  - `.models-snapshot.json` / changelog page and latest-date data — `pnpm generate:models` / `pnpm generate:changelog`.

## Commands

- `pnpm dev` / `pnpm build` / `pnpm start`
- `pnpm test` — vitest unit tests (`lib/**/*.test.*`)
- `pnpm lint:docs` — docs authoring-contract check (also runs at `prebuild`)
- `pnpm generate:openapi` / `pnpm generate:cli` — regenerate the reference sections (both run at `prebuild`)
- `pnpm generate:config` / `pnpm lint:config` — generate/check the configuration reference and downloadable schema from the pinned snapshot
- `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>` — capture a committed upstream schema with provenance and checksum
- `pnpm snapshot:cli` — re-capture the CLI snapshot from the local `bitrouter` binary (set `BITROUTER_BIN` to override the path)
- `pnpm generate:models` / `pnpm generate:changelog` — refresh the models snapshot and latest-changelog data
