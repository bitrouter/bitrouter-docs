# bitrouter-docs

Next.js 16 (App Router) + fumadocs site for [bitrouter.ai](https://bitrouter.ai) — landing, models catalog, recipes, blog, changelog, and the documentation under `content/docs/`.

## Documentation rules

- **English only.** The site no longer ships localized docs — do not create `<name>.zh.md` translation files or reintroduce i18n plumbing. Old `/zh/*` URLs 301 to the English pages via `next.config.ts` redirects.
- Docs are **`.mdx`**, import-free, using only the whitelisted global components — see `docs/CONTRIBUTING.md` for the full authoring contract. Write Markdown; the extension is what makes `<Callout>` / `<Cards>` / `<Tabs>` actually render (fumadocs-mdx picks its processor by extension, and `.md` silently drops those blocks).
- Lint with `pnpm lint:docs` (`scripts/check-docs.mjs`) after editing docs.
- Documentation is one unified Fumadocs page tree with no layout tabs. Its seven user-facing groups are **Overview, Coding Agents, Routing, Model, Context, CLI, API**. In `content/docs/meta.json`, each group name is a native Fumadocs separator and each meta-only `*-nav` folder is extracted into the root, so group labels are not clickable or collapsible. Changelog is a separate top-level `/changelog` section with its own `content/changelog/` source and release-version sidebar.
- **Show every non-Reference page in the sidebar exactly once unless it is an explicit product-navigation exception.** Overview, Coding Agents, Routing, Model, Context, CLI, and API use flat link lists beneath their separators, with Comparison as an explicit collapsed-folder exception under Overview; do not hide detailed pages or introduce other nested guide folders by default. Intentional hidden pages must remain rare and be listed in `HIDDEN_SIDEBAR_ROUTES` in `scripts/check-docs.mjs`; currently Self-hosting, BitRouter Agent, the supporting Request receipts guide, the compatibility CLI manual, and the retained Coding agents guide are hidden. Local Models is visible. `pnpm lint:docs` enforces this coverage.
- **Overview order is Quickstart, Supported Models, How BitRouter Works, then Comparison.** How BitRouter Works retains `/docs/overview/what-is-bitrouter`.
- **Overview contains a collapsed Comparison folder.** Its header only expands/collapses the folder, with no index page; its four children are OpenRouter, Router (Ramp), vLLM Semantic Router, and LiteLLM. `(comparison-nav)/meta.json` projects those canonical pages into Overview. Keep competitor claims sourced to current official documentation and qualify deployment/build availability. The retired `/docs/overview/comparison` URL redirects to the first child. Point content links and legacy migration redirects directly at the corresponding child.
- **API and CLI each contain a collapsed Reference folder.** API has three flat guides (Responses (default), Decisions / System One, and Chat Completions / Messages), followed by `content/docs/reference/` as a native folder preserving generated API families and endpoints. CLI keeps its operational guides flat and places generated command-group pages inside Reference. Make reference hierarchy changes in `scripts/generate-openapi.mjs` and `scripts/generate-cli.mjs`, never in generated metadata.
- **Model** has exactly four visible guides: Virtual Models (named model endpoints, selectors, request profiles, and compatibility), Model Fallback (failure-driven replacement), BYOK & Subscriptions (credentials, accounts, and custom endpoints), and Local Models (self-run inference). **Routing** has exactly four visible guides: Configuration (YAML) (common file mechanics and policy artifacts), Model Routing (candidate eligibility and selection mechanics), Context Routing (native evidence views), and Strategies (existing routing approaches, customization, adequacy, objective evaluations, and reviewed publication). All four are public canonical guides under `/docs/routing/`. **Context** shows ACP servers, MCP servers, Agent Skills, and AGENTS.md, with their configuration and usage. Native context selection belongs to Routing, separately from Context's tool, agent, and instruction connections. Both Server tools guides are retired during refactoring. **CLI** shows Self-driving, Interactive TUI, Headless & Scripting, and generated references. Self-driving (full page title Self-driving Workflows, retaining `/docs/cli/orchestrator` and the product name BitRouter Orchestrator/BRO in its body) and Interactive TUI are goal-oriented design previews based on 006 PRD v0.8, pending implementation validation; Headless & Scripting covers development-native `bro task run` / `bro task managed`, structured output, verification, and Goal automation boundaries; full Goal scripting remains unverified. External one-prompt ACP invocation and approval policies live in ACP servers, linked from the generated command reference. Native launch belongs to Coding Agents and does not create a Goal. Keep captured CLI reference output source-faithful until a verified binary snapshot supports the new contract. Configuration is canonical at `/docs/routing/configuration`; the former CLI configuration URL redirects there. Request receipts remains directly accessible and linked from feature guides, without a sidebar entry. **Coding Agents** owns `bro [harness]` launch configuration and product-specific coding-agent guides. **API** owns Responses (default), Decisions / System One, Chat Completions / Messages, and generated endpoints. Keep each configuration example with the feature it configures; share it through links. Self-hosting owns deployment operations and OTLP exporter setup, content capture, and sampling. Enterprise is the Overview decision entry.
- Retiring or moving a page means adding a 301 to the `pairs` list in `next.config.ts` — that file is the URL history of the docs.
- **Always use the scripts — never hand-edit generated output.** Anything produced by a generator is regenerated at `prebuild`, so manual edits are silently lost:
  - API reference (`content/docs/reference/<tag>/`) — edit `openapi.yaml`, then `pnpm generate:openapi`.
  - CLI references (`content/docs/(guide)/cli/reference/*.mdx`, plus the compatibility manual at `cli/reference.mdx`) — edit `cli-overlays/index.md` (page intro) or `cli-overlays/<group>.md` (a `##` section), then `pnpm generate:cli`.
  - `.cli-snapshot.json` — re-capture from the binary with `pnpm snapshot:cli`; never edit by hand.
  - `.models-snapshot.json` / changelog-latest data — `pnpm generate:models` / `pnpm generate:changelog`.

## Commands

- `pnpm dev` / `pnpm build` / `pnpm start`
- `pnpm test` — vitest unit tests (`lib/**/*.test.*`)
- `pnpm lint:docs` — docs authoring-contract check (also runs at `prebuild`)
- `pnpm generate:openapi` / `pnpm generate:cli` — regenerate the reference sections (both run at `prebuild`)
- `pnpm snapshot:cli` — re-capture the CLI snapshot from the local `bitrouter` binary (set `BITROUTER_BIN` to override the path)
- `pnpm generate:models` / `pnpm generate:changelog` — refresh the models snapshot and latest-changelog data
