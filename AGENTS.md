# bitrouter-docs

Next.js 16 (App Router) + fumadocs site for [bitrouter.ai](https://bitrouter.ai) — landing, models catalog, recipes, blog, changelog, and the documentation under `content/docs/`.

## Documentation rules

- **English only.** The site no longer ships localized docs — do not create `<name>.zh.md` translation files or reintroduce i18n plumbing. Old `/zh/*` URLs 301 to the English pages via `next.config.ts` redirects.
- Docs are **`.mdx`**, import-free, using only the whitelisted global components — see `docs/CONTRIBUTING.md` for the full authoring contract. Write Markdown; the extension is what makes `<Callout>` / `<Cards>` / `<Tabs>` actually render (fumadocs-mdx picks its processor by extension, and `.md` silently drops those blocks).
- Lint with `pnpm lint:docs` (`scripts/check-docs.mjs`) after editing docs.
- Documentation is one unified Fumadocs page tree with no layout tabs. Its eight user-facing groups are **Overview, Usage, Coding Agents, Routing, Model, Market, Context, Reference**. In `content/docs/meta.json`, each group name is a native Fumadocs separator and each meta-only `*-nav` folder is extracted into the root, so group labels are not clickable or collapsible. Changelog is one page at `/docs/changelog` under Reference, generated from `content/changelog/`; old release URLs redirect to version anchors. RSS/Atom stay at `/changelog/rss.xml` and `/changelog/atom.xml`.
- **Show every non-Reference page in the sidebar exactly once unless it is an explicit product-navigation exception.** Overview, Usage, Coding Agents, Routing, Model, Market, Context, and Reference use flat link lists beneath their separators, with Comparison under Overview and API reference under Reference as explicit collapsed-folder exceptions; do not hide detailed pages or introduce other nested guide folders by default. Intentional hidden pages must remain rare and be listed in `HIDDEN_SIDEBAR_ROUTES` in `scripts/check-docs.mjs`; currently Cloud, Supported Models, Self-hosting, BitRouter Agent, the supporting Request receipts guide, the shared `bro [harness]` guide, and the retained Coding agents guide are hidden. Local Models is visible. `pnpm lint:docs` enforces this coverage.
- **Overview order is Quickstart, How BitRouter Works, Inference Spot, Inference Forwards, then Comparison.** Inference Spot and Inference Forwards are Coming soon placeholders. Supported Models remains accessible at `/docs/overview/supported-models` without a sidebar entry. How BitRouter Works retains `/docs/overview/what-is-bitrouter`.
- **Overview contains a collapsed Comparison folder.** Its header only expands/collapses the folder, with no index page; its four children are OpenRouter, Router (Ramp), vLLM Semantic Router, and LiteLLM. `(comparison-nav)/meta.json` projects those canonical pages into Overview. Keep competitor claims sourced to current official documentation and qualify deployment/build availability. The retired `/docs/overview/comparison` URL redirects to the first child. Point content links and legacy migration redirects directly at the corresponding child.
- **Usage** contains exactly Desktop, CLI, Responses API, MCP, and Web, in that order. MCP and Web are Coming soon placeholders. The Cloud placeholder remains accessible at `/docs/usage/cloud` without a sidebar entry. Usage MCP is separate from the Context MCP servers configuration/use guide. Desktop is Coming soon until its implementation is verified. CLI combines Self-driving, Interactive TUI, and Headless & Scripting at `/docs/usage/cli`, retaining all preview qualifications. **Reference** contains Changelog (one page), Data handling (a Coming soon placeholder), CLI reference (one generated page at `/docs/cli/reference`), config reference (one schema-generated page at `/docs/configuration-reference`), and API reference (the collapsed `content/docs/reference/` folder, with every endpoint directly visible after one expansion, static family separators, and its supporting Decisions / System One and Chat Completions / Messages guides). Make generated hierarchy changes in the scripts, never generated metadata.
- **Model** owns model access, source connections, and callable interfaces, with exactly five visible guides in this order: Model Fallbacks, Model Variants, Virtual Models, BYOK & Subscriptions, and Local Models. These guides live under `/docs/models-routing/`. Model owns credentials, subscription accounts, custom endpoints, self-run inference, selectors, request profiles, compatibility, and fallback configuration. Custom Provider is retired; its URL redirects to the custom endpoints section of BYOK & Subscriptions. **Market** follows Model and contains Buy Inference and Sell Inference at `/docs/market/`. Model Variants, Buy Inference, and Sell Inference currently have titles and descriptions only; detailed content and marketplace implementation remain unverified. Market owns buying and selling workflows and future trading, delivery, and settlement guides. Connecting an endpoint belongs to Model; offering its inference for sale belongs to Market. Routing explains runtime selection among sources the caller can already access, including BYOK, local, private, and purchased sources. Buying or selling inference is optional; routing does not grant access or purchase supply. Keep feature configuration examples in their owning Model guides and link to them from Routing. **Routing** has exactly four visible guides: Configuration (YAML) (common file mechanics and policy artifacts), Model Routing (candidate eligibility and selection mechanics), Context Routing (native evidence views), and Strategies (existing routing approaches, customization, adequacy, objective evaluations, and reviewed publication). All four are public canonical guides under `/docs/routing/`. **Context** shows ACP servers, MCP servers, Agent Skills, and Server tools. Server tools currently has a title and description only while its implementation is being refactored. Native context selection belongs to Routing, separately from Context's tool, agent, and instruction connections. The former Config Server tools guide is retired; its URL redirects to the Context placeholder. **Usage > CLI** combines Self-driving workflows, Interactive TUI, and Headless & Scripting. Self-driving (retaining the product name BitRouter Orchestrator/BRO in its body) and Interactive TUI are goal-oriented design previews based on 006 PRD v0.8, pending implementation validation; Headless & Scripting covers development-native `bro task run` / `bro task managed`, structured output, verification, and Goal automation boundaries; full Goal scripting remains unverified. External one-prompt ACP invocation and approval policies live in ACP servers, linked from the generated command reference. Native launch belongs to Coding Agents and does not create a Goal. Keep captured CLI reference output source-faithful until a verified binary snapshot supports the new contract. Configuration is canonical at `/docs/routing/configuration`; the former CLI configuration URL redirects there. Request receipts remains directly accessible and linked from feature guides, without a sidebar entry. **Coding Agents** shows Claude Code, Codex, DeepSeek Harness, OpenCode, and Pi, in that order. These product-specific pages are Coming soon placeholders. The shared `bro [harness]` launch guide remains accessible at `/docs/integration/bro-harness` without a sidebar entry. **Usage > Responses API** owns the default generation guide; **API reference** owns Decisions / System One, Chat Completions / Messages, and generated endpoints. Keep each configuration example with the feature it configures; share it through links. Self-hosting owns deployment operations and OTLP exporter setup, content capture, and sampling. Enterprise is the Overview decision entry.
- Retiring or moving a page means adding a 301 to the `pairs` list in `next.config.ts` — that file is the URL history of the docs.
- **Always use the scripts — never hand-edit generated output.** Anything produced by a generator is regenerated at `prebuild`, so manual edits are silently lost:
  - API reference (`content/docs/reference/<tag>/`) — edit `openapi.yaml`, then `pnpm generate:openapi`.
  - CLI reference (`content/docs/(guide)/cli/reference.mdx`) — edit `cli-overlays/index.md` (page intro) or `cli-overlays/<group>.md` (a `##` section), then `pnpm generate:cli`.
  - config reference (`content/docs/configuration-reference.mdx`) and downloadable schema — edit `config-reference/index.md` for prose; refresh the pinned upstream schema with `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>`, then `pnpm generate:config`. Never hand-edit `config-reference/schema.json`, `config-reference/source.json`, or `public/schemas/bitrouter.config.schema.json`.
  - `.cli-snapshot.json` — re-capture from the binary with `pnpm snapshot:cli`; never edit by hand.
  - `.models-snapshot.json` / changelog page and latest-date data — `pnpm generate:models` / `pnpm generate:changelog`.

## Commands

- `pnpm dev` / `pnpm build` / `pnpm start`
- `pnpm test` — vitest unit tests (`lib/**/*.test.*`)
- `pnpm lint:docs` — docs authoring-contract check (also runs at `prebuild`)
- `pnpm generate:openapi` / `pnpm generate:cli` — regenerate the reference sections (both run at `prebuild`)
- `pnpm generate:config` / `pnpm lint:config` — generate/check the configuration reference and downloadable schema from the pinned snapshot
- `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>` — capture a committed upstream schema with provenance and checksum
- `pnpm snapshot:cli` — re-capture the CLI snapshot from the local `bitrouter` binary (set `BITROUTER_BIN` to override the path)
- `pnpm generate:models` / `pnpm generate:changelog` — refresh the models snapshot and latest-changelog data
