# bitrouter-docs

Next.js 16 (App Router) + fumadocs site for [bitrouter.ai](https://bitrouter.ai) — landing, models catalog, recipes, blog, changelog, and the documentation under `content/docs/`.

## Documentation rules

- **English only.** The site no longer ships localized docs — do not create `<name>.zh.md` translation files or reintroduce i18n plumbing. Old `/zh/*` URLs 301 to the English pages via `next.config.ts` redirects.
- Docs are **`.mdx`**, import-free, using only the whitelisted global components — see `docs/CONTRIBUTING.md` for the full authoring contract. Write Markdown; the extension is what makes `<Callout>` / `<Cards>` / `<Tabs>` actually render (fumadocs-mdx picks its processor by extension, and `.md` silently drops those blocks).
- Lint with `pnpm lint:docs` (`scripts/check-docs.mjs`) after editing docs.
- Documentation is one unified Fumadocs page tree with no layout tabs. Its eight user-facing groups are **Overview, Usage, Coding Agents, Market, Router, Model, Context, Reference**. In `content/docs/meta.json`, each group name is a native Fumadocs separator and each meta-only `*-nav` folder is extracted into the root, so group labels are not clickable or collapsible. Changelog is one page at `/docs/changelog` under Reference, generated from `content/changelog/`; old release URLs redirect to version anchors. RSS/Atom stay at `/changelog/rss.xml` and `/changelog/atom.xml`.
- **Show every non-Reference page in the sidebar exactly once unless it is an explicit product-navigation exception.** Overview, Usage, Coding Agents, Market, Router, Model, Context, and Reference use flat link lists beneath their separators, with Comparison under Overview and API reference under Reference as explicit collapsed-folder exceptions; do not hide detailed pages or introduce other nested guide folders by default. Intentional hidden pages must remain rare and be listed in `HIDDEN_SIDEBAR_ROUTES` in `scripts/check-docs.mjs`; currently the supporting Context Routing and Configuration (YAML) guides, Cloud, Self-hosting, BitRouter Agent, the supporting Request receipts guide, the shared `bro [harness]` guide, and the retained Coding agents guide are hidden. Local Models is visible. `pnpm lint:docs` enforces this coverage.
- **Overview order is Quickstart, How BitRouter Works, Models, Elastic Inference, then Comparison.** Models restores the catalog at `/docs/overview/supported-models`. Elastic Inference at `/docs/overview/elastic-inference` is an authored product overview of the optional cloud service, covering price, time, heterogeneous models, the electricity-exchange vision, and illustrative buy/sell limit-order tables and JSON. Its concise description replaces a duplicate introductory paragraph; an opening info Callout explains that the Cloud service is optional, BitRouter OSS works without it, and links to Auto Router. JSON follows the supplied order-design spec and is labeled provisional, without inventing an HTTP endpoint or released API contract. Its approved copy is prepared for post-deployment publication and is not evidence of live availability. Keep purchase validity separate from completion timing, preserve maximum-charge budget checks, and link to all five Market guides from What’s next in sidebar order. The retired Inference Spot and Inference Forwards pages 301 here. How BitRouter Works retains `/docs/overview/what-is-bitrouter`.
- **Overview contains a collapsed Comparison folder.** Its header only expands/collapses the folder, with no index page; its four children are OpenRouter, Router (Ramp), vLLM Semantic Router, and LiteLLM. `(comparison-nav)/meta.json` projects those canonical pages into Overview. Keep competitor claims sourced to current official documentation and qualify deployment/build availability. The retired `/docs/overview/comparison` URL redirects to the first child. Point content links and legacy migration redirects directly at the corresponding child.
- **Usage** contains exactly Desktop, CLI, Responses API, MCP, and Web, in that order. MCP and Web are Coming soon placeholders. The Cloud placeholder remains accessible at `/docs/usage/cloud` without a sidebar entry. Usage MCP is separate from the Context MCP servers configuration/use guide. Desktop is Coming soon until its implementation is verified. CLI combines Self-driving, Interactive TUI, and Headless & Scripting at `/docs/usage/cli`, retaining all preview qualifications. **Reference** contains Changelog, Privacy Policy, Terms of Service, Troubleshooting, and API reference, in that order. Privacy Policy and Terms of Service are authored docs pages at `/docs/privacy-policy` and `/docs/terms-of-service`; migrate their existing prose without changing policy commitments. Troubleshooting is a Coming soon placeholder. API reference remains the collapsed `content/docs/reference/` folder, with static family separators and directly visible endpoints plus the Decisions and compatibility guides. CLI command reference is embedded in `/docs/usage/cli#command-reference`; schema-generated configuration reference is embedded in `/docs/routing/configuration#configuration-reference`. Data handling is retired and redirects to Privacy Policy. Make generated hierarchy changes in scripts, never generated metadata.
- **Market** follows Coding Agents and precedes Router. It contains Buy Inference, Sell Inference, Agentic Payment, Auto-bidding, and Market Data, in that order, at `/docs/market/`. Buy Inference and Sell Inference currently have titles, descriptions, and links to State Affinity; Agentic Payment, Auto-bidding, and Market Data are Coming soon placeholders. Detailed marketplace behavior remains unverified. Market owns buying and selling workflows and future trading, delivery, and settlement guides. Connecting an endpoint belongs to Model; offering its inference for sale belongs to Market.
- **Router** contains exactly Auto Router, Workload Optimization, State Affinity, Routing Traces, and Strategies, in that order. Its five main guides live under `/docs/routing/`: `auto-router`, `workload-optimization`, `state-affinity`, `routing-traces`, and `strategies`. Auto Router owns setup, policy binding initialization, per-call overrides, and serving-route inspection. Workload Optimization combines a Coming soon overview of learning from user-defined recurring agentic workloads with a clearly separate existing policy-tools section. It owns policy artifacts, runtime adequacy, objective evaluation evidence, reproducibility boundaries, and reviewed publication; the planned learning feature does not automatically publish candidates or introduce unverified commands. Routing Traces owns following router behavior across the available workflow trajectory: requested versus serving routes, correlation, retries/fallbacks, recorded decision evidence, usage, and coverage limits. Use existing receipts and OTLP export rather than inventing a unified timeline UI or complete external-harness visibility. The former Auditable Policies URL 301s to Routing Traces; retain its historical section anchors as links to the migrated Workload Optimization sections. Redirect legacy policy/evaluation URLs directly to those sections. Strategies owns selector resolution, candidate eligibility, preset filters, named `variants:`, and ordering limits. Routing Rules redirects to Strategies; Model Variants redirects to its Variants section. State Affinity remains the canonical Coming soon guide for state-aware source selection; Market owns its trading applications. Context Routing and Configuration (YAML) remain directly accessible supporting guides linked from Strategies, intentionally absent from the five-entry Router sidebar and listed in `HIDDEN_SIDEBAR_ROUTES`. Context Routing owns native evidence views; Configuration retains file mechanics and its generated inline schema reference. Preserve legacy section anchors on Auto Router and Strategies while internal links target each section's current owner. Routing uses sources the caller already has access to; it does not purchase supply or grant access. Keep rule examples in Strategies and policy lifecycle examples in Workload Optimization.
- **Model** owns source connections and callable interfaces, with exactly five visible guides in this order: Model Fallbacks, Virtual Models, Structured Output, BYOK & Subscriptions, and Local Models. Model owns credentials, subscription accounts, custom endpoints, self-run inference, named endpoints, request defaults, protocol compatibility, and fallback configuration. Named routing variants belong to Router rather than Model. Custom Provider is retired; its URL redirects to the custom endpoints section of BYOK & Subscriptions. Keep feature configuration examples in their owning guides and link to them from Router.
- **Context** shows ACP servers, MCP servers, Agent Skills, Server tools, and Context Switcher, in that order. Context Switcher is a Coming soon placeholder at `/docs/context-routing/context-switcher`; it does not replace the existing Context Routing supporting guide or its historical redirects. Server tools currently has a title and description only while its implementation is being refactored. Native context selection belongs to Router, separately from Context's tool, agent, and instruction connections. The former Config Server tools guide is retired; its URL redirects to the Context placeholder. **Usage > CLI** combines Self-driving workflows, Interactive TUI, and Headless & Scripting. Self-driving (retaining the product name BitRouter Orchestrator/BRO in its body) and Interactive TUI are goal-oriented design previews based on 006 PRD v0.8, pending implementation validation; Headless & Scripting covers development-native `bro task run` / `bro task managed`, structured output, verification, and Goal automation boundaries; full Goal scripting remains unverified. External one-prompt ACP invocation and approval policies live in ACP servers, linked from the generated command reference. Native launch belongs to Coding Agents and does not create a Goal. Keep captured CLI reference output source-faithful until a verified binary snapshot supports the new contract. Configuration is canonical at `/docs/routing/configuration`; the former CLI configuration URL redirects there. Request receipts remains directly accessible and linked from feature guides, without a sidebar entry. **Coding Agents** shows Claude Code, Codex, DeepSeek Harness, OpenCode, and Pi, in that order. Claude Code and Codex are authored CLI integration guides with four sections: prerequisites and launch; official environment/TOML proxy configuration for local and Cloud; default model pool and customization; Verify & troubleshoot. Claude Code examples use only Claude models and Codex examples use only GPT models. Example pools are explicit configuration, not automatically installed policies or account-availability guarantees. Keep Codex native model metadata separate from route eligibility, and distinguish gateway credentials, API-key sources, and local subscriptions. DeepSeek Harness, OpenCode, and Pi remain Coming soon placeholders. The shared `bro [harness]` launch guide remains accessible at `/docs/integration/bro-harness` without a sidebar entry. **Usage > Responses API** owns the default generation guide; **API reference** owns Decisions / System One, Chat Completions / Messages, and generated endpoints. Keep each configuration example with the feature it configures; share it through links. Self-hosting owns deployment operations and OTLP exporter setup, content capture, and sampling. Enterprise is the Overview decision entry.
- Retiring or moving a page means adding a 301 to the `pairs` list in `next.config.ts` — that file is the URL history of the docs.
- **Always use the scripts — never hand-edit generated output.** Anything produced by a generator is regenerated at `prebuild`, so manual edits are silently lost:
  - API reference (`content/docs/reference/<tag>/`) — edit `openapi.yaml`, then `pnpm generate:openapi`.
  - CLI guide and inline command reference (`content/docs/(guide)/usage/cli.mdx`) — edit `cli-overlays/guide.md` for the workflow guide, `cli-overlays/index.md` for the reference intro, or `cli-overlays/<group>.md` for command sections, then `pnpm generate:cli`. The full published CLI page is generated; never edit it directly.
  - Configuration guide with inline schema reference (`content/docs/(guide)/routing/configuration.mdx`) and downloadable schema — edit `config-reference/guide.md` for the configuration workflow or `config-reference/index.md` for reference prose; refresh the pinned upstream schema with `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>`, then `pnpm generate:config`. Never hand-edit `config-reference/schema.json`, `config-reference/source.json`, or `public/schemas/bitrouter.config.schema.json`.
  - `.cli-snapshot.json` — re-capture from the binary with `pnpm snapshot:cli`; never edit by hand.
  - `.models-snapshot.json` / changelog page and latest-date data — `pnpm generate:models` / `pnpm generate:changelog`.

## Commercial pricing

- The top-level `/models` page is an Elastic Inference market design preview, separate from platform Pricing and the broad documentation catalog. Its only assumed listings are `glm-5.3`, `kimi-k3`, `glm-5.3-flash`, and `deepseek-v4.1-flash`, with stable demo observations in `lib/elastic-market.ts`, no backend API or live-availability claim. Desktop defaults to Table; mobile defaults to one-column Cards; desktop Cards use two or three columns. Remember explicit layout choice. Use shadcn Charts for quote steps and fulfilled-token volume. Market buyer prices include 5%, using a fixed 3:1 input/output, no-cache, standard-delivery reference profile; legacy supplier snapshots still exclude the fee. Preserve catalog detail URLs. Demo market routes remain noindex and outside the sitemap. `/pricing#models` links to the new market page.
- Its four global metrics are Trading Volume, Available Liquidity, Avg. Slippage, and Platform Fees. `lib/elastic-market-metrics.ts` owns deterministic settlement-cohort and independent-capacity demo fixtures. Volume is settled supplier USD excluding platform fees; Fees sums the corresponding recorded Elastic fees. Both, plus Slippage, use the selected 24H/7D/30D period by settlement time. Liquidity remains the current snapshot: 3K input/1K output, no cache, accept now, complete within five minutes, within 5% above each model's lowest eligible ask, valued before platform fees; shared capacity must be allocated once. Slippage compares the selected supplier's purchase-decision quote with accepted contract rates on the same actual usage, weighted by reference cost, with sample/coverage and adverse P95 disclosed. Do not confuse budget headroom, output-length prediction, or intentional waiting with execution slippage. Missing benchmarks show unavailable, not zero. Keep market-wide totals independent of model search and preserve clear Demo labels.
- Each global metric has a compact shadcn Chart beside its value: interval bars for settled Volume/Fees, a step line for historical liquidity snapshots, and weighted interval Slippage with a zero baseline. Use hourly/6-hour/daily buckets for 24H/7D/30D; amounts reconcile to headline totals, while liquidity's latest point matches the current headline. Preserve missing observations as gaps and keep all historical fixtures deterministic. Never fabricate live refresh activity or derive slippage by averaging bucket percentages.
- Models uses a compact trading-board layout: metrics, controls, and market data take priority. Keep a small page title and Demo/snapshot status; no marketing hero, slogan, or explanatory footer. Move metric and quote definitions into accessible information popovers, including on asset detail pages. Fixed demo snapshots must not be labeled Live or given fake refresh activity.
- Each assumed model detail is a trading-workspace preview: compact ticker and fixed reference profile, quote/volume history, order book and cumulative depth, Buy/Sell Quote Preview, and Recent Trades / Suppliers / Specifications / My Orders tabs. Reuse independent liquidity allocations; count complete reference requests, never normalize arbitrary buyer budgets into bids. Custom quote estimates use expected output, while budget checks use the full output limit plus the 5% fee; purchase validity and post-acceptance completion are separate. Previews never submit orders or reserve supply. Accepted activity has no settled usage/amount; the tape is an illustrative sample, not the full aggregate ledger. Supplier performance is demo data, developer and supplier are distinct, unverified model capabilities stay unverified, and My Orders has an account-not-connected state.
- Elastic Inference is the canonical product name and `/docs/overview/elastic-inference` is its overview route. Keep `/docs/overview/flex-inference` and the older Spot/Forwards/market-name aliases as direct 301s to this route. Preserve `what-is-flex-inference` / `why-flex-inference` section anchors and the `/pricing#flex-inference` anchor as URL history; all current labels, links, metadata, commercial IDs, and market modules use the new name.
- Its essential filters are Developer (OR within the selected model developers, distinct from inference sellers), maximum buyer Best ask, and Has bids; combine groups with AND and the existing search. Counts respect the other groups. Filter cards and table together without changing global metrics. Desktop has a left sidebar; smaller screens use a keyboard-accessible filter drawer with immediate results, individual active-filter removal, and reset. Do not invent context-window, modality, or capability metadata for the assumed listings. Card columns follow the listing container width, with one column on mobile.

- OSS self-hosting is free of BitRouter fees; provider and infrastructure costs remain separate.
- Cloud Auto Routing with BYOK is $0.01 per million verifiable routing input tokens actually processed by the cloud routing service. Provider inference, including generation output, is billed separately. Do not substitute provider inference usage for the routing input meter.
- Elastic Inference adds a 5% buyer transaction fee to the supplier’s actual settled charge. It has no separate Cloud Auto Routing fee; buyer caps include the transaction fee. Do not apply Liquid’s token floors or invent minimums, failed-request rules, or retry billing semantics.
- Enterprise pricing stays custom. Payment-processing charges remain a separate category.
- `lib/commercial-pricing.ts` owns the four website pricing options. The homepage presents a compact OSS-free heading, two Cloud pricing options, and one Pricing link; the dedicated Pricing page retains all four full options. Keep homepage, Pricing/FAQ, model-rate labels, structured metadata, LLM discovery, and affected docs consistent. Catalog snapshots remain supplier rates; never alter snapshots to bake in the platform fee.
- These are user-approved publication terms. Website changes do not implement or validate Cloud billing. Preserve existing refund/privacy commitments unless separately authorized.

## Commands

- `pnpm dev` / `pnpm build` / `pnpm start`
- `pnpm test` — vitest unit tests (`lib/**/*.test.*`)
- `pnpm lint:docs` — docs authoring-contract check (also runs at `prebuild`)
- `pnpm generate:openapi` / `pnpm generate:cli` — regenerate the reference sections (both run at `prebuild`)
- `pnpm generate:config` / `pnpm lint:config` — generate/check the configuration reference and downloadable schema from the pinned snapshot
- `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>` — capture a committed upstream schema with provenance and checksum
- `pnpm snapshot:cli` — re-capture the CLI snapshot from the local `bitrouter` binary (set `BITROUTER_BIN` to override the path)
- `pnpm generate:models` / `pnpm generate:changelog` — refresh the models snapshot and latest-changelog data
