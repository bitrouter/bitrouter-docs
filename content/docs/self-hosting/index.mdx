---
title: Self-hosting BitRouter
description: Run the Apache-2.0 router on your own infrastructure with one binary and your own provider credentials.
---

BitRouter self-hosted is one binary in the request path between your agents and model providers. It needs no external database, queue, container runtime, or sidecar for a local deployment.

## Start locally

```bash
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/bitrouter/bitrouter/releases/latest/download/bitrouter-installer.sh | sh
export OPENAI_API_KEY=sk-...        # any provider key in the environment is auto-detected
bro start                           # http://127.0.0.1:4356
```

This starts a loopback-only router with local authentication skipped. No config or database is required until you opt into features that need them.

## Decide how far to deploy

| Goal | Add |
| --- | --- |
| Use BitRouter on one workstation | Provider credentials and `bro start` |
| Keep it running on one host | A pinned binary, committed config, and process supervisor |
| Let another machine call it | TLS, `skip_auth: false`, and virtual keys |
| Preserve identity, metering, or adaptive evidence | SQLite, Postgres, or MySQL plus backups |

The open-source binary includes protocol translation, routing, guardrails, server tools, MCP/ACP integration, and OpenTelemetry export. BitRouter Cloud adds managed provider access, billing, and a hosted control plane; it does not replace the local binary.

<Callout type="info">
You can attach a Cloud account with `bro cloud login` while continuing to route through your own provider accounts from the same process.
</Callout>

## Persistence is optional

Routing decisions come from configuration. A database becomes important only when you use:

- **Virtual keys** — the `users` and `api_keys` tables behind `bro key sign`, when you authenticate callers.
- **Metering** — the `requests` table, per-request cost accounting.
- **The adequacy ledger** — the evidence tables the adaptive routing loop learns from.

SQLite is the default. Postgres and MySQL use the same binary. See [Operate](/docs/self-hosting/operate#state-and-backups) before depending on stored identity or history.
