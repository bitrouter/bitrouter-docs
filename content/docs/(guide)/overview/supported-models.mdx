These are the models **hosted BitRouter** currently supports. Request a catalog model ID to route among eligible providers and fall back after retryable failures. The hosted catalog focuses on models for agentic and coding workloads.

The self-hosted proxy can also route to your own local or remote models, including fine-tunes and private endpoints: see [bring your own model](/docs/config/providers#custom-endpoints-and-models). To use your own provider credentials with the local proxy, see [bring your own provider](/docs/config/providers#built-in-providers-with-your-own-key).

Prices are USD per **million tokens** from the currently available provider with the lowest combined uncached input and text output rates. They are catalog reference rates, not a guarantee of the price paid on every request: the selected provider, cache use, and context tier can change the charge. `—` means a rate is unavailable in the catalog. **Modalities** are the inputs a model accepts; every model returns text. The public, open-source [registry](https://github.com/bitrouter/bitrouter/tree/main/registry) can also contain providers that are not currently reachable in the hosted service.

## How model ids work

On BitRouter a "model" is not a single endpoint. It's an **aggregate**: one logical model — say `openai/gpt-4o` or `anthropic/claude-sonnet-4.6` — that can be served by many providers at once. You address it by the stable **model id** in the catalog above, and BitRouter decides which underlying provider endpoint actually answers each request. That indirection is the point: you write your agent against `anthropic/claude-sonnet-4.6`, and the set of providers behind it can grow, shrink, or re-price without you changing a line of code.

Cloud filters eligible providers by request capabilities and ranks them using price, observed latency, throughput, and health. Hosted routing profiles such as `:cost`, `:latency`, and `:throughput` bias the ranking toward that dimension; they do not guarantee a particular provider. For the self-hosted alpha.33 proxy, [model resolution](/docs/models-routing/models) uses configured priority and deterministic fallback order instead of live cost or latency ranking.

## Calling these models

The hosted catalog is available through one account at `api.bitrouter.ai`, without upstream provider keys or per-provider signups. Billing uses the selected route's provider token rates with 0% token markup, and model routing is included. Third-party payment-processing fees may apply when adding funds; those top-up fees are separate from model pricing.

```bash
bro cloud login   # one-time device-flow sign-in
bro start         # the `bitrouter` provider auto-enables once signed in
```
