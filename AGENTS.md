# bitrouter-docs

Next.js 16 (App Router) + fumadocs site for [bitrouter.ai](https://bitrouter.ai) — landing, models catalog, recipes, blog, changelog, and the documentation under `content/docs/`.

## Documentation rules

- **English only.** The site no longer ships localized docs — do not create `<name>.zh.md` translation files or reintroduce i18n plumbing. Old `/zh/*` URLs 301 to the English pages via `next.config.ts` redirects.
- Docs are **`.mdx`**, import-free, using only the whitelisted global components — see `docs/CONTRIBUTING.md` for the full authoring contract. Write Markdown; the extension is what makes `<Callout>` / `<Cards>` / `<Tabs>` actually render (fumadocs-mdx picks its processor by extension, and `.md` silently drops those blocks).
- Lint with `pnpm lint:docs` (`scripts/check-docs.mjs`) after editing docs.
- Documentation is one unified Fumadocs page tree with no layout tabs. Its eight user-facing groups are **Overview, Usage, Coding Agents, Market, Router, Model, Context, Reference**. In `content/docs/meta.json`, each group name is a native Fumadocs separator and each meta-only `*-nav` folder is extracted into the root, so group labels are not clickable or collapsible. Changelog is one page at `/docs/changelog` under Reference, generated from `content/changelog/`; old release URLs redirect to version anchors. RSS/Atom stay at `/changelog/rss.xml` and `/changelog/atom.xml`.
- **Show every non-Reference page in the sidebar exactly once unless it is an explicit product-navigation exception.** Overview, Usage, Coding Agents, Market, Router, Model, Context, and Reference use flat link lists beneath their separators, with Comparison under Overview and API reference under Reference as explicit collapsed-folder exceptions; do not hide detailed pages or introduce other nested guide folders by default. Intentional hidden pages must remain rare and be listed in `HIDDEN_SIDEBAR_ROUTES` in `scripts/check-docs.mjs`; currently the supporting Context Routing and Configuration (YAML) guides, Cloud, Self-hosting, BitRouter Agent, the supporting Request receipts guide, the shared `bro [harness]` guide, and the retained Coding agents guide are hidden. Local Models is visible. `pnpm lint:docs` enforces this coverage.
- **Overview order is Quickstart, How BitRouter Works, Models, Flex Inference, then Comparison.** Models restores the catalog at `/docs/overview/supported-models`. Flex Inference at `/docs/overview/flex-inference` is an authored product overview of the optional cloud service, covering price, time, heterogeneous models, the electricity-exchange vision, and illustrative buy/sell limit-order tables and JSON. Its concise description replaces a duplicate introductory paragraph; an opening info Callout explains that the Cloud service is optional, BitRouter OSS works without it, and links to Auto Router. JSON follows the supplied order-design spec and is labeled provisional, without inventing an HTTP endpoint or released API contract. Its approved copy is prepared for post-deployment publication and is not evidence of live availability. Keep purchase validity separate from completion timing, preserve maximum-charge budget checks, and link to all five Market guides from What’s next in sidebar order. The retired Inference Spot and Inference Forwards pages 301 here. How BitRouter Works retains `/docs/overview/what-is-bitrouter`.
- **Overview contains a collapsed Comparison folder.** Its header only expands/collapses the folder, with no index page; its four children are OpenRouter, Router (Ramp), vLLM Semantic Router, and LiteLLM. `(comparison-nav)/meta.json` projects those canonical pages into Overview. Keep competitor claims sourced to current official documentation and qualify deployment/build availability. The retired `/docs/overview/comparison` URL redirects to the first child. Point content links and legacy migration redirects directly at the corresponding child.
- **Usage** contains exactly Desktop, CLI, Responses API, MCP, and Web, in that order. MCP and Web are Coming soon placeholders. The Cloud placeholder remains accessible at `/docs/usage/cloud` without a sidebar entry. Usage MCP is separate from the Context MCP servers configuration/use guide. Desktop is Coming soon until its implementation is verified. Privacy Policy and Terms of Service are authored docs pages at `/docs/privacy-policy` and `/docs/terms-of-service`; migrate their existing prose without changing policy commitments. Troubleshooting is a Coming soon placeholder. - Retiring or moving a page means adding a 301 to the `pairs` list in `next.config.ts` — that file is the URL history of the docs.
- **Always use the scripts — never hand-edit generated output.** Anything produced by a generator is regenerated at `prebuild`, so manual edits are silently lost:
  - API reference (`content/docs/reference/<tag>/`) — edit `openapi.yaml`, then `pnpm generate:openapi`.
  - CLI guide and inline command reference (`content/docs/(guide)/usage/cli.mdx`) — edit `cli-overlays/guide.md` for the workflow guide, `cli-overlays/index.md` for the reference intro, or `cli-overlays/<group>.md` for command sections, then `pnpm generate:cli`. The full published CLI page is generated; never edit it directly.
  - Configuration guide with inline schema reference (`content/docs/(guide)/routing/configuration.mdx`) and downloadable schema — edit `config-reference/guide.md` for the configuration workflow or `config-reference/index.md` for reference prose; refresh the pinned upstream schema with `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>`, then `pnpm generate:config`. Never hand-edit `config-reference/schema.json`, `config-reference/source.json`, or `public/schemas/bitrouter.config.schema.json`.
  - `.cli-snapshot.json` — re-capture from the binary with `pnpm snapshot:cli`; never edit by hand.
  - `.models-snapshot.json` / changelog page and latest-date data — `pnpm generate:models` / `pnpm generate:changelog`.

## Commercial pricing

- OSS self-hosting is free of BitRouter fees; provider and infrastructure costs remain separate.
- Cloud Auto Routing with BYOK is $0.01 per million verifiable routing input tokens actually processed by the cloud routing service. Provider inference, including generation output, is billed separately. Do not substitute provider inference usage for the routing input meter.
- Flex Inference adds a 5% buyer transaction fee to the supplier’s actual settled charge. It has no separate Cloud Auto Routing fee; buyer caps include the transaction fee. Do not apply Liquid’s token floors or invent minimums, failed-request rules, or retry billing semantics.
- Enterprise pricing stays custom. Payment-processing charges remain a separate category.
- `lib/commercial-pricing.ts` owns the four website pricing options. The homepage presents a compact OSS-free heading, two Cloud pricing options, and one Pricing link; the dedicated Pricing page retains all four full options. Keep homepage, Pricing/FAQ, model-rate labels, structured metadata, LLM discovery, and affected docs consistent. Catalog snapshots remain supplier rates; never alter snapshots to bake in the platform fee.
- These are user-approved publication terms. Website changes do not implement or validate Cloud billing. Preserve existing refund/privacy commitments unless separately authorized.

## Commands

- `pnpm dev` / `pnpm build` / `pnpm start`
- `pnpm test` — vitest unit tests (`lib/**/*.test.*`)
- `pnpm lint:docs` — docs authoring-contract check (also runs at `prebuild`)
- `pnpm generate:openapi` / `pnpm generate:cli` — regenerate the reference sections (both run at `prebuild`)
- `pnpm generate:config` / `pnpm lint:config` — generate/check the configuration reference and downloadable schema from the pinned snapshot
- `pnpm snapshot:config --repo <checkout> --ref <commit-or-tag>` — capture a committed upstream schema with provenance and checksum
- `pnpm snapshot:cli` — re-capture the CLI snapshot from the local `bitrouter` binary (set `BITROUTER_BIN` to override the path)
- `pnpm generate:models` / `pnpm generate:changelog` — refresh the models snapshot and latest-changelog data
