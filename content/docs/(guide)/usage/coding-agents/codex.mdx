---
title: Codex
description: Run Codex through BitRouter and optionally use a ChatGPT Plus or Pro subscription as its model source.
---

Codex is a harness: it owns the agent loop and tools. BitRouter supplies its model route, fallback, policy, and metering.

## Pick a mode

```bash
bro code codex                         # BitRouter conversation
bro run codex "Summarize this repo"   # headless ACP turn
bro codex                              # Codex's native interface
```

`bro launch codex` is the generic spelling of `bro codex`. It injects a temporary `bitrouter` model provider into the child process and does not edit `~/.codex/config.toml`.

Verify the executable, daemon, and route before a long run:

```bash
bro launch codex --check
```

## Select a model

Pin a daemon-routable model with BitRouter's option:

```bash
bro codex --model bitrouter/auto
bro launch codex --model openai/gpt-5-codex
```

Arguments after `--` go directly to Codex. Avoid forwarding Codex `-c` or `--config` overrides that replace the injected provider; `bro launch` rejects known conflicting shapes.

## Permanent configuration

Use a permanent provider block only when Codex must start outside `bro launch`:

```toml
model_provider = "bitrouter"

[model_providers.bitrouter]
name = "BitRouter"
base_url = "http://127.0.0.1:4356/v1"
wire_api = "responses"
# env_key = "BITROUTER_API_KEY"
```

For Cloud, use `https://api.bitrouter.ai/v1`, set `env_key = "BITROUTER_API_KEY"`, and export a BitRouter key. An authenticated self-hosted daemon requires the same.

<Callout type="warning">
Codex model-provider configuration belongs in the user-level `~/.codex/config.toml`. Project-local Codex configuration does not define model providers.
</Callout>

## Use a Codex subscription

The `openai-codex` provider uses a ChatGPT Plus or Pro credential and the Codex Responses backend. It is separate from the standard `openai` API-key provider, but it can be used with the Codex harness described above.

Sign in:

```bash
bro providers login openai-codex
```

BitRouter can import a compatible local Codex login or start the provider's browser flow. For automation that must not open a browser:

```bash
bro providers login openai-codex --import-existing --no-browser
```

No `providers:` block is required. Verify the models and route:

```bash
bro models --provider openai-codex
bro route openai-codex:gpt-5-codex
```

Use the provider-qualified id to require the subscription source. A request routed to `openai:<model>` uses `OPENAI_API_KEY` and the public OpenAI API instead.

Then launch any Codex mode normally:

```bash
bro start
bro codex
# or: bro code codex
# or: bro run codex "Summarize this repo"
```

Sign out with:

```bash
bro providers logout openai-codex
```

This removes BitRouter's stored subscription credential. It does not sign the Codex CLI out of its own account.

<Callout type="info">
Provider login and BitRouter Cloud login are separate. `bro providers login openai-codex` authenticates the upstream subscription; `bro cloud login` authenticates your BitRouter account.
</Callout>
